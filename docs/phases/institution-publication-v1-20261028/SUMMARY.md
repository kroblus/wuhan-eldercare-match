# 架构第 5 项：机构资料在线维护与发布

2026-10-28。按 Owner 选择实现网页后台、人工确认、版本发布和小程序在线读取。源码在主工作区，未部署生产服务、未微信上传或发布。

## 现在能做什么

- 在现有管理员网页新建机构草稿、编辑名称、所属地区代码/名称、公开介绍、价目等；复杂机构字段通过展开的完整记录编辑，复用严格 V1.2.1 校验。稳定 ID 为 2–100 位小写字母、数字及连字符，一个院区改名仍沿用原 ID。地区必须人工填写，修改身份字段会撤销该字段的旧核验关联，不自动授予核验资格。
- 人工填写来源引用、确认人、确认日期，确认绑定当次内容；修改后撤销确认。发布生成新的不可变机构版本，旧版本和原始证据不覆盖。并发编辑、外部工具推进版本、重复发布均有明确冲突或原操作回执。
- 公开介绍、机构核验事实和平台服务资格各自管理。公示价与标签不会变成已核验护理能力；“发布”不会自动开放接单。服务资格单独变更，新申请读取当前选项，历史申请与带看保留当时名称，结果未确认的原申请仍可按原编号重试。
- 小程序普通目录和推荐可读取同一在线当前目录；咨询页可浏览多机构公开介绍。推荐详情接入精确历史版本，目录更新后仍读取原推荐引用的版本，不换成最新记录。

## 数据流与边界

`admin-web/publications.js → /api/v1/p1-service/admin/institutions → 旧机构版本库 + 发布审计/公开介绍 → /api/v1/institution-publications → 小程序`

管理员复用现有 cookie、CSRF 和登录生命周期。发布在同一事务中检查草稿版本、确认内容摘要与当前基础版本，写入机构版本、公开介绍和发布回执；同 operationId 内容不符返回冲突。目录只包含当前已发布版本，历史按 institutionId + recordRevision 精确读取。环境归属检查阻止合成数据进入正式公开池，并发首次导入也必须核对归属。

未配置在线 origin 时沿用现有随构建目录。配置后只使用在线目录，不拼接本地目录；网络、模式、schema 或身份关联失败明确报错，不把旧事实当作在线成功。普通目录和推荐拒绝合成环境；开发版咨询页允许合成公开资料，但显示醒目标识。Demo 不读取这个 origin、存储或网络。

人工“确认可发布”不等于各字段取得核验资格。原记录的 unknown/unavailable/unverified/expired/false、证据路径、核验日期和有效期仍由原契约校验。没有新增真实机构事实、老人数据、收费或结算模块。

## 首次正式接入步骤

这些是后续部署步骤，本轮没有执行真实导入或开启正式服务。

1. 部署已有后端及 Flyway V12，配置现有管理员账号、数据库和 Node 校验运行时。`INSTITUTION_PUBLICATIONS_ENABLED` 默认 false，确认准备就绪后再开启；`P1_INTAKE_ENABLED` 和 C2 写入仍各自独立。
2. 在主根执行 `npm run build:production`，再执行 `npm run export:institution-publication-baseline`。只在本地生成 `output/institution-publication-baseline/baseline.json`，不联网、不发布；已有文件不覆盖。也可传入新的 output 文件路径。
3. 管理员在“导入现有目录”选择该文件，填写迁移来源并明确确认保留旧事实和核验日期。支持 `{catalog,historicalRecords}` 导出文件及原纯 catalog；历史记录只入版本库，不混入当前目录。不一致的同 ID/版本拒绝覆盖。当前导出实测为 11 条 current、0 条历史，全部现有版本为 1。
4. 为需要公示的机构维护公开介绍并人工确认、发布；基线导入本身不补造介绍、价目或确认事实。需要平台对接的机构另行维护服务资格。
5. 将获批 HTTPS 公共地址配置到 `modes/production/runtime/institution-publication-origin.ts`，配置微信合法域名后重新构建、按既有流程验收上线。该地址不含凭证，也不会启用私有身份/申请服务。首次切源前应核对导入后的完整当前目录。

仅开发调试可临时设置 `__dev_institution_publication_origin_v1`，遵循现有受限内网 origin 校验；与 C5 私有 origin 分开，release 忽略开发存储。调试后清除该 key。真实申请仍需要独立 C5、获批告知、平台联系方式及服务配置。

- 后台 DOM/API 的 96 项断言通过，覆盖编辑、确认、幂等重试、冲突、独立服务资格、基线导入与历史记录分离、登出后迟到响应。真实 HTTP 联调发现新建机构缺少必填地区输入，已补显式地区字段和未填拦截，未放宽领域校验。
- 目录读取、V2 评估/推荐、C1 计算/组合/页面、机构详情交互、VR、能力证据、P1、模式隔离和卡片操作相关回归通过。旧测试中新增微信 API 使用的 stub 已按真实“未配置”行为补齐，未放宽业务断言。
- 后端最终相关检查合计 61 组通过：发布 15 组、原 P1 43 组、Node 校验器 3 组。实际隔离 MySQL/HTTP 覆盖旧版本不变、事务回滚、跨环境并发归属、确认失效、重复操作、独立资格、旧申请恢复及名称快照。空模板经真实校验验证：缺地区明确返回受限 code/path，补齐并重新确认后发布成功，不回显字段值或整条资料。旧 Node 测试把连接不可用（SQLState 08001）误当技术错误的断言已依据原实现纠正，同时补 42000 技术错误断言；实现未放宽，后续单跑 3 组通过，早先失败日志保留。[各套件最终证据](../../../output/institution-publications-20261028/final-validation.json)。
- 11 家静态基线通过服务器打包的严格 Node 校验器和行政区规则，只读校验没有数据库写入。实际 HTTP 完成合成机构第 1、2 版发布、原版精确读取、原发布操作重放和独立服务资格启停；编译后小程序公开 client 实际读取第 2 版，普通正式目录如预期拒绝合成池。证据见 [HTTP 联调结果](../../../output/institution-publication-v1-20261028/http-client-integration.json)。
