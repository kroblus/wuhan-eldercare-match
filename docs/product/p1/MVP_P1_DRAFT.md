## 1. 一句话定位

面向武汉家庭提供免费的机构浏览、养老需求整理和带看预约服务；朋友通过一个网页工作台管理需求、联系家属与机构、安排带看、记录服务结果并导出获客报表。

小程序不是交易平台：不收款、不支付、不计佣、不结算、不签合同。朋友与养老机构在线下签约，其商业安排不进入本软件。机构价目表用于公开了解和预算参考，不是平台收费。对外可写“免费养老咨询与看院对接”；不因免费自行宣称已取得慈善组织身份、政府背书或养老入住本身免费。

## 2. 用户明确的范围

| 保留或新增 | 如何落实 |
|---|---|
| 机构性质 | 记录民办非营利、民办营利、公办、公建民营等实际类别；不扩建合同主体和收款主体管理 |
| 院区与地址 | 由朋友现场核实后录入，记录确认人和日期；仍需保存正确院区/入口供看院使用，不建多层审批 |
| 咨询电话 | 使用朋友提供的号码，界面写“平台咨询/预约咨询/专属顾问”；不冒充机构官方电话；实际号码由朋友在后台配置 |
| 展示标签 | 可展示“医养结合”等机构介绍标签，保留来源；展示标签不自动等于医疗资质、医务室或具体护理接收能力 |
| 术后/短托 | 本轮口述暂理解为“术后康养、短期托养”，记录朋友确认提供；专业康复治疗能力和短住收费不据此推断 |
| 后台 | 一个网页版工作台，朋友为首期主要操作者；不额外要求各机构注册商家账号 |
| 带看 | 家庭提出意向，朋友联系双方后确认具体时间；必须防本人/家属时间冲突 |
| 报表 | 内部可授权查看必要明细；对机构默认导出不含可识别个人信息的获客汇总 |

“术后康养”是对口述的上下文整理，正式标签用词可由朋友在资料录入时确认，不因这个字词阻塞其他开发。

## 3. 最小业务路线

**家庭：** 浏览机构/整理需求 → 联系平台或申请带看 → 查看“待安排” → 朋友确认后查看时间/集合点 → 实际到访 → 可选反馈。

**朋友：** 登录网页 → 查看新需求和待安排 → 联系家属与机构 → 日历安排且检查冲突 → 确认/改期/取消 → 记录到访及后续反馈 → 选择日期与机构导出报表。

用户不必填完旧32题才能浏览或申请普通咨询。预约可以只包含必要联系人、目标机构和意向时段；健康信息按实际用途另行提供。申请成功不是时间已确认。

## 4. P0必须做，什么明确不做

| 模块 | 可验收成果 |
|---|---|
| 机构展示 | 正确性质、地址、标签、分档价目表、平台咨询入口；没有实景/VR就不伪造 |
| 需求接收 | 简短需求及自愿联系，后台能收到同一记录，重复提交不会重复建单 |
| 网页需求列表 | 筛选日期、区域、预算、照护情况、意向机构、来源、跟进状态；查看必要摘要及下次联系 |
| 带看排期 | 意向时段与最终时间分开，朋友/同一家庭冲突检查，改期、取消和实际到访 |
| 报表导出 | 单机构与平台整体分开，真实/演示分开，人次/去重需求分开，导出有筛选范围和数据口径 |
| 基础权限 | 后台登录、用户仅看本人记录、后台与导出API鉴权；不把真实健康资料放入GitHub/开发Drive |

明确不做：合同管理、电子签章、机构年费、佣金计算、支付、账单、对账结算、开票、资金统计。也不做机构自助APP、多租户ERP、复杂审批、地图自动规划路线和另建同步服务。

## 5. 页面安排

用户小程序复用现有首页、机构列表/详情、轻量需求/摘要、顾问入口、带看申请/进度、我的记录。首页卡片可显示“民办非营利”“医养结合”“双人间”“参考总月费3600—7200元”等；待核实条件在详情说明，不给未知能力自动加分。

网页工作台五个入口：**工作概览、老人需求、带看日历、机构资料、报表中心**。首期以朋友单人操作为主；后续真有协作者再扩权限，不先造企业组织架构。

## 6. 首家机构收费依据已更新

新增材料：《柠月颐养中心入住价格公示表（2026年）》，适用房型为双人间。总月费依公示护理等级为3600/4200/5100/6300/7200元。床位费固定1800元、伙食费900元；首次入住另列医疗备用金5000元、床品900元。

新价目表澄清旧手填数字；旧3600—7000和“押金5000/一次性900”的表述只保留为历史来源，当前展示按公示项目名与金额更新。医疗备用金不是已证实可退押金；不猜退款、抵扣、按天折算和报价截止日。短托日费/最短天数单独待机构提供，不从月费除30得出。

## 7. 获客报表如何证明服务价值

统计访问、需求提交、可联系需求、已联系、带看申请、已确认、实际到访，及有依据的后续入住反馈；不记录收费或佣金。

默认对机构输出“本机构服务成果”：该机构关联需求、已确认看院、实际到访家庭与人次、已确认后续结果，另附必要的预算/区域/照护需求分布。平台整体潜在需求单列，不能算作每家机构已获客。重复预约、电话按钮点击、Demo测试和线下人工录入分别标识，不伪造平台增长。

首期重点为Excel：报告总览、需求画像汇总、机构服务漏斗、统计口径四个页签；统一样式、清晰标题和图表、打印布局。可打印PDF是展示层增强，不作为第一条闭环的前置工程。内部跟进明细不与对外报告放在同一工作簿，即使隐藏页也不允许。

## 8. 实施顺序

1. 机构资料/价目表/平台电话与网页工作台基础、最小需求接收。
2. 带看申请到后台排期、冲突提示、双方确认和到访反馈。
3. 基于上述同一数据库记录的获客统计与Excel导出。

每步交付一条能用的业务链；不要求全部30页重写，也不为了报表先做大型数据仓库。详细问卷和C2历史在需要时复用。当前文档只在本轮修订，代码基线仍为GitHub现有HEAD。
